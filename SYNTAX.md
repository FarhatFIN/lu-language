# Lu/Strict — синтаксис v5

Переработка черновика «Мой синтаксис новый для Lu». Теги (`incl`, `vid`, `Pr`,
`dv`, `Del`, `pack`) и идея битов в объявлении — ваши и остались. Заменена
механика: то, что читалось только с документом в руках, теперь читается само.

Три правила, из которых выведено всё остальное:

1. **Один смысл — одна запись.** Никаких сокращений «на выбор».
2. **Объявление нельзя пропустить.** Нет переменной без типа, нет присваивания
   без `set`, нет функции без `fn`.
3. **Читатель кода важнее автора.** Синтаксис должен расшифровываться без
   этого файла.

---

## 1. Как выглядит программа

```lu
Lu/Strict

incl <std/io>

vid LIMIT: int = 100

pack byte Flags {
    vid0..1 lit: bool = false
    vid2..3 mode: byte = 0
    vid4..7 code: byte = 0
}

struct Hero {
    pub name: str
    pub hp: int
    secret: int
}

fn clamp(value: int, low: int, high: int) -> int {
    if value < low {
        ret low
    }
    if value > high {
        ret high
    }
    ret value
}

fn main() -> int {
    var h: Hero
    set h.name = "Lu"
    set h.hp = clamp(120, 0, LIMIT)
    Pr(h.name, h.hp)

    var i: int = 0
    loop 3 {
        set i = i + 1
        if i == 2 {
            continue
        }
        Pr(i)
    }

    vid topics: str[2] = ["Арифметика", "Переменные"]
    for t in topics {
        Pr(t)
    }

    if "Арифметика" in topics {
        Pr("найдено")
    }

    var p: ptr/byte = Alloc(8)
    Memset(p, 0, 8)
    Del p
    ret 0
}
```

## 2. Что из черновика выжило

| Черновик | v5 | Почему |
|---|---|---|
| `incl <Библеотека>` | `incl <std/io>` | тег и углы ваши; путь через `/`, опечатка исправлена |
| `vid <переменная>` | `vid x: int = 0` | объявления без типа не существует |
| `vid01 <x>` — 2 бита | `pack byte { vid0..1 x: bool }` | биты только внутри упаковки — иначе неясно, чей это байт |
| `Pr("text");` | `Pr("text")` | `;` нет нигде |
| `Pr010` | `PrBits(x)` | биты принадлежат переменной, а не печати |
| `dv(x)` | `dv(&x)` | ввод принимает место и возвращает `bool` — «прочиталось или нет» |
| `if(содержание: "A" "B")` | `if t in ["A", "B"] { }` | `if` остаётся булевым, список — обычный литерал |
| `Del[x]` | `Del x` | `[]` означает индексацию и ничего больше |
| `Scruct` | `struct` | опечатку в ключевом слове нельзя исправить никогда |
| `prv[...]` / `pub` | `pub` перед полем; приватное по умолчанию | модификатор принадлежит полю, а не региону |
| `Mas010* <M>`, `M[3,45]` | `vid m: int[2] = [3, 45]` | тип элемента уже говорит, что там числа |
| `Pr(Massive&)` | `for x in m { Pr(x) }` | `&` — только адрес |

`prv` убран намеренно: если отсутствие `pub` уже означает приватность, ключевое
слово `prv` ничего не сообщает. Меньше слов — строже правила.

## 3. Лексика

- **Комментарии:** `// до конца строки`, `/* ... */`.
- **Строки:** `"..."` и `«...»` — обе формы, экранирование `\n \t \" \\`.
- **Числа:** `42`, `0x2a`, `0b101010`, `1_000_000`.
- **Имена:** буква или `_`, далее буквы, цифры, `_`. Кириллица в именах
  запрещена: имена — латиница, тексты — любые.
- **Конец оператора — перевод строки.** Точки с запятой нет и не будет.
  Внутри `(`, `[`, `{` перевод строки не имеет значения.
- **Отступы не значимы.** Блок задаётся только `{ }`.

Маркер `Lu/Strict` в первой строке обязателен: файл v4 и файл v5 не должны
молча компилироваться как один и тот же язык.

## 4. Объявления

```lu
Lu/Strict

fn main() -> int {
    vid  x: int = 0      // неизменяемая привязка, значение задано здесь
    var  y: int = 0      // изменяемая
    var  z: int = 0
    set  z = z + 1       // единственный способ изменить
    ret z
}
```

- **`vid` нельзя переприсвоить.** `set x = ...` для `vid` — ошибка компиляции.
- **Неинициализированных значений нет.** Объявление без `=` даёт нулевое
  значение своего типа (у `str` — пустую строку), а не «мусор», как в C++.
  Поэтому `var h: Hero` безопасно: структура обнулена целиком.
- **Присваивание — оператор, не выражение.** `x = y = 0` не существует.
- **Тип обязателен всегда.** `vid x = 0` — ошибка `missing type`.
- **Одно объявление на оператор.** `vid a: int = 0, b: int = 0` — ошибка.
- **Затенение запрещено.** Повторный `vid x` во вложенном блоке — ошибка.

### Типы

| Тип | Размер | Замечание |
|---|---|---|
| `byte` | 1 | беззнаковый 0..255 |
| `int` | 4 | знаковый |
| `int64` | 8 | знаковый |
| `bool` | 1 | только `true` / `false` |
| `str` | 8 | указатель на неизменяемые байты, всегда с завершающим нулём |
| `ptr/T` | 8 | указатель на `T` |
| `T[N]` | `N × sizeof(T)` | массив фиксированной длины |
| `void` | — | только как тип результата |

`float` в ядре нет. Нет и неявных преобразований — вот это компилируется по
грамматике, но отвергается проверкой типов:

```lu
Lu/Strict

fn main() -> int {
    vid b: byte = 200
    vid i: int = b
    ret 0
}
```

```
error: implicit conversion byte -> int; write int(b)
```

Правильно: `vid i: int = int(b)`.

### Память

```lu
Lu/Strict

fn main() -> int {
    var p: ptr/byte = Alloc(64)   // 64 элемента типа, на который указывает p
    var q: ptr/byte = Alloc(64)
    Memset(p, 0, 64)
    Memcpy(q, p, 64)
    Del p                         // и p больше нельзя использовать
    Del q
    ret 0
}
```

- `Alloc(n)` возвращает `ptr/T` по объявленному типу переменной.
- `Del p` освобождает и **запрещает** дальнейшее использование `p` в этой
  области: `p[0]` после `Del p` — ошибка `use after Del`, а не падение в рантайме.
- Двойной `Del p` — ошибка.
- `null` нет. `ptr/T` всегда либо указывает на память, либо переменной не
  существует.

## 5. Биты: `pack`

Единственное место, где объявляются битовые поля.

```lu
pack byte Flags {
    vid0..1 lit: bool = false
    vid2..3 mode: byte = 0
    vid4..7 code: byte = 0
}
```

- `vid0..1` читается буквально: **от бита 0 до бита 1**. Ведущий `0` — нулевой
  бит, как в вашем черновике.
- Вторая цифра — последний бит. `vid0..1` — 2 бита, `vid0..7` — байт,
  `vid0..20` — 21 бит. Разница видна глазом, таблица в голове не нужна.
- `pack byte Flags` объявляет **тип** `Flags` и его единицу хранения (`byte`).
  Поля обязаны лежать внутри неё и **не пересекаться**: `vid0..3` и `vid3..5` —
  ошибка `overlapping bit fields`.
- Дырки разрешены: `vid0..1` + `vid4..7` оставляет биты 2–3 нулевыми.
- Вне `pack` диапазон битов — ошибка `bit range outside pack`.
- Поле читается и пишется как обычная переменная. Компилятор сам делает
  `and`/`or`/сдвиг; в коде этого не видно.

```lu
pack byte Small {
    vid0..1 lit: bool = false
}

fn main() -> int {
    var f: Small
    set f.lit = true
    if f.lit {
        Pr("включено")
    }
    ret 0
}
```

Печать поля с шириной — отдельная функция, а не режим `Pr`:

```text
PrBits(f.lit)     // 1
PrBits(f.mode)    // 00..11 по ширине поля
```

## 6. Структуры и доступ

```lu
struct Hero {
    pub name: str
    pub hp: int
    secret: int
}
```

- Приватное — по умолчанию. `pub` открывает поле.
- Методы — внутри структуры, `fn` как везде:

```lu
struct Hero {
    pub hp: int

    fn alive(self) -> bool {
        ret self.hp > 0
    }
}
```

- `self` — имя получателя, задаётся явно. Никакого неявного `this`.
- Наследования нет. Композиция и указатели — есть.
- Присваивание структуры копирует значение целиком. Указатель копирует адрес.

## 7. Управление

```text
if cond { ... } else { ... }
if cond { ... } else if cond { ... } else { ... }
while cond { ... }
loop 3 { ... }                  // ровно 3 итерации
for x in arr { ... }
for i in 0..10 { ... }          // 0..10 — полуинтервал
match v { case 1 { ... } else { ... } }
```

Правила:

- **Условие обязано быть `bool`.** `if x` для `x: int` — ошибка
  `condition must be bool; write x != 0`. Никакой истинности по ненулевому
  значению, как в Python и C++.
- **Блок обязателен.** `if c ret 0` — ошибка. Однострочных `if` нет.
- **`match` без `else` допустим только для `bool` и перечислений.** Для `str`
  и чисел `else` обязателен — исчерпывающе проверить их нельзя.
- **`match` сравнивает содержимое `str`, а не адреса.** Это отличается от v4 и
  записано здесь как правило языка, а не как пожелание.
- **`break` и `continue`** работают в `while`, `loop`, `for`. В `loop`
  `continue` всё равно увеличивает счётчик.
- **`ret` обязателен на каждом пути** функции с не-`void` результатом. Проверка
  статическая.

## 8. Функции

```lu
fn name(a: int, b: str) -> int {
    ret a
}
```

- `-> T` опускается только для `void`.
- Перегрузки нет. Два `fn f` с одним именем — ошибка.
- Значения по умолчанию запрещены.
- Вариативных аргументов нет, кроме `Pr`, который встроен.
- До 6 параметров (ограничение нативного бэкенда; больше — ошибка, а не
  молчаливая порча стека).

`main` — обычная функция:

```lu
fn main() -> int {
    ret 0
}
```

Код возврата `main` — код выхода процесса в обоих бэкендах. `fn main() -> void`
даёт 0.

Точки входа на верхнем уровне нет: исполняемый код живёт только внутри
функций. Верхний уровень — объявления.

## 9. Ввод и вывод

```text
Pr(value)              // по типу, с новой строки
Pr("x =", x)           // несколько аргументов — через пробел
PrBits(x)              // двоичное представление по ширине типа
dv(&x)                 // прочитать значение в x; результат — bool
```

`dv` возвращает `bool`, и его нельзя проигнорировать молча:

```lu
Lu/Strict

fn main() -> int {
    var n: int = 0
    if dv(&n) {
        Pr("прочитано:", n)
    } else {
        Pr("конец ввода")
    }
    ret 0
}
```

Форматных строк нет. `Pr("%d", x)` — ошибка: строка печатается как строка,
значения передаются значениями. Это убирает целый класс ошибок
`printf`-формата вместе с самой возможностью их допустить.

---

## 10. Файлы

```lu
incl <std/io>
incl <mylib/ui>
```

- Один `incl` — один файл. Путь через `/`, без кавычек и без `.lu`.
- Повторный `incl` того же файла игнорируется.
- Циклический `incl` — ошибка с перечнем цикла.

## 11. Что запрещено — и почему это жёстче Python и C++

| Запись | Ошибка | Чем лучше |
|---|---|---|
| `x = 5` | `undeclared name 'x'` | нет случайного создания переменной опечаткой |
| `set x = 5` для `vid` | `cannot assign to immutable 'x'` | намерение изменить видно в объявлении |
| `vid x = 5` | `missing type` | тип не выводится из значения |
| `if x` где `x: int` | `condition must be bool` | нет `0`/`""`/`None` как лжи |
| `int i = b` где `b: byte` | `implicit conversion` | расширение всегда написано |
| `x++` | `no increment operator` | одно действие — одна запись |
| `vid a: int = 0, b: int = 0` | `one declaration per statement` | диффы и ошибки не смешиваются |
| повторный `vid x` | `shadowing forbidden` | имя означает ровно одну вещь |
| `fn f()` дважды | `overloading forbidden` | вызов однозначен по имени |
| `fn f(a: int = 0)` | `default arguments forbidden` | арность всегда известна |
| `Pr("%d", x)` | `format strings forbidden` | нет расхождения формата и типа |
| `if c ret 0` | `block required` | нет висящих `else` |
| `match s { ... }` без `else` | `non-exhaustive match` | нет забытой ветки |
| `p[0]` после `Del p` | `use after Del` | висячий указатель ловится компилятором |
| `var` на верхнем уровне | `global mutable state forbidden` | нет скрытого состояния между вызовами |
| `null` | `no null literal` | нет разыменования пустоты |
| `ret` не на всех путях | `missing return` | нет «иногда возвращает мусор» |

Проверяется это не на словах: примеры ниже обязаны разбираться, а следующие
четыре — обязаны не разбираться.

```lu-bad
Lu/Strict

fn main() -> int {
    Pr("x");
    ret 0
}
```

```lu-bad
Lu/Strict

fn main() -> int {
    x = 5
    ret 0
}
```

```lu-bad
Lu/Strict

struct Hero {
    vid0..1 lit: bool
}
```

```lu-bad
Lu/Strict

fn main() -> int {
    if true ret 0
    ret 1
}
```

Все двенадцать примеров этого документа разобраны эталонным парсером по §12, а
четыре блока выше отвергнуты на лексеме `;`, на не-вызове в позиции оператора,
на `vid0..1` вне `pack` и на отсутствующем блоке после `if`. Когда появится
фронтенд v5, эту же роль будет играть сам `luc`.

Итого 20 ключевых слов против 35 у Python и ~95 у C++:
`incl, vid, var, set, pub, fn, struct, if, else, while, loop, for, in, match,
case, pack, Del, ret, break, continue`.

## 12. Грамматика

```ebnf
program   = "Lu/Strict" { item } ;
item      = incl | global | struct | pack | fn ;
incl      = "incl" "<" path ">" ;
path      = IDENT { "/" IDENT } ;
global    = "vid" IDENT ":" type [ "=" expr ] ;

struct    = "struct" IDENT "{" { field | method } "}" ;
field     = [ "pub" ] IDENT ":" type [ "=" expr ] ;
method    = "fn" IDENT "(" [ params ] ")" [ "->" type ] block ;

fn        = "fn" IDENT "(" [ params ] ")" [ "->" type ] block ;
params    = param { "," param } ;
param     = "self" | IDENT ":" type ;

type      = "ptr/" typeatom | typeatom [ "[" INT "]" ] ;
typeatom  = "byte" | "int" | "int64" | "bool" | "str" | "void" | IDENT ;

block     = "{" { stmt } "}" ;
stmt      = bind | assign | if | while | loop | for | match
          | free | call | ret | "break" | "continue" ;

bind      = ( "vid" | "var" ) IDENT ":" type [ "=" expr ] ;
assign    = "set" place "=" expr ;
place     = IDENT { "[" expr "]" | "." IDENT } ;

if        = "if" expr block [ "else" ( if | block ) ] ;
while     = "while" expr block ;
loop      = "loop" expr block ;
for       = "for" IDENT "in" expr block ;
match     = "match" expr "{" { case } "}" ;
case      = "case" expr block | "else" block ;

pack      = "pack" typeatom IDENT "{" { bitfield } "}" ;
bitfield  = BITNAME ".." INT IDENT ":" typeatom [ "=" LITERAL ] ;
          (* BITNAME = "vid" + цифры: vid0, vid3, vid20 — первый бит поля *)

free      = "Del" place ;
call      = "Pr" "(" [ args ] ")" | "dv" "(" "&" IDENT ")"
          | IDENT "(" [ args ] ")" ;
args      = expr { "," expr } ;
ret       = "ret" [ expr ] ;

expr      = logic_or ;
logic_or  = logic_and { "||" logic_and } ;
logic_and = compare  { "&&" compare } ;
compare   = sum { ( "==" | "!=" | "<" | "<=" | ">" | ">=" | "in" ) sum } ;
sum       = product { ( "+" | "-" ) product } ;
product   = unary { ( "*" | "/" | "%" ) unary } ;
unary     = ( "-" | "!" | "&" ) unary | postfix ;
postfix   = primary { "[" expr "]" | "." IDENT | "(" [ args ] ")" } ;
primary   = INT | STR | "true" | "false" | IDENT | "(" expr ")"
          | "[" [ expr { "," expr } ] "]" ;
LITERAL   = INT | STR | "true" | "false" ;
```

Операторы заканчиваются переводом строки; `NL` в грамматике опущен, потому что
он не создаёт неоднозначности — кроме `ret`, где отсутствие выражения
определяется концом строки.

## 13. Как это ляжет на существующий компилятор

Почти всё — тонкий слой над уже существующими узлами AST:

| Конструкция v5 | Узел AST |
|---|---|
| `vid` / `var` | `NODE_VAR_DECL` |
| `vid x: ptr/T = ...` | `NODE_PTR_DECL` |
| `set x = e` | `NODE_SET` |
| `fn` | `NODE_FUNC_DECL` |
| `struct` | `NODE_STRUCT_DECL` |
| `if` / `while` | `NODE_IF` / `NODE_LOOP_WHILE` |
| `loop N` | `NODE_LOOP` |
| `for x in a` | `NODE_LOOP_EACH` |
| `match` | `NODE_MATCH` |
| `Del` | `NODE_FREE` |
| `Alloc` / `Memset` / `Memcpy` | `NODE_ALLOC` / `NODE_MEMSET` / `NODE_MEMCPY` |
| `incl` | `NODE_INCLUDE` |
| `Pr` | `NODE_PR` |

**Единственная по-настоящему новая работа — `pack`.** Он требует: разложить
поля по единице хранения, проверить пересечения, породить `and`/`or`/сдвиг при
чтении и записи в обоих бэкендах. Всё остальное — новый разбор поверх готового
AST, то есть часы, а не недели.

Проверки строгости (неявные преобразования, `use after Del`, исчерпывающий
`match`, `vid`-присваивание) — это расширение `semantic.c`, а он сейчас
выполняется только для C-бэкенда. Для v5 его придётся включать всегда.

## 14. Открытые вопросы

1. **`vid` неизменяем по умолчанию** — так строже и так меньше ошибок, но
   писать `var` придётся чаще. Если окажется неудобно, поменять местами можно
   одним решением, пока нет кода.
2. **`str[2]` — массив ссылок или копий?** В спеке — ссылок: строки неизменяемы,
   копировать их незачем.
3. **Коды ошибок.** Раз исключений нет, функции возвращают `int`-код или
   `bool`. Нужен ли общий тип `Res` — вопрос следующего шага.
4. **Ширина полей в `pack` больше 64 бит** — запрещена: единица хранения
   максимум `int64`.
